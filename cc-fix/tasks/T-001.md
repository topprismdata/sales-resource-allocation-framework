### ⚠️ 已实测的坑（不处理必然失败）

1. **`fence` 字段超长**：`csv.DictReader` 默认上限 131072，直接读会抛
   `_csv.Error: field larger than field limit (131072)`。
   **必须在读取前执行**：
   ```python

   csv.field_size_limit(sys.maxsize)
   ```
2. **坐标系 = GCJ-02**（已实测冻结，见 CONTRACTS §1.1）。
   围栏 CSV 与路网 geojson **同系**，直接比对误差 0.0017m。
   若误判为 WGS84 会产生 **623.8m** 系统位移。
   → `meta.json` 必须声明 `"crs": "GCJ-02"`，**不要在本任务中做任何坐标转换**
   （服务端 `pack_from_disk()` 会在加载时统一转 WGS-84）。

## 输出（必须精确匹配）

### `data/gz/region.json`

**⚠️ 2026-08-31 拓扑修订**：实测 71 条围栏中有 **11 条 MultiPolygon**（最多 7 组件）
与 **9 条含内环**（共 60 个洞）。schema 已按下述规则修订。

```json
{
  "fences": [
    {"area_id": "694419783#1", "src_area_id": "694419783", "component": 1,
     "components_total": 7, "dealer": "珠海市龙进贸易有限公司",
     "area_km2": 1.234, "rings": [[[113.08, 23.83], ...]],
     "holes": [[[113.09, 23.84], ...]]}
  ],
  "stores": [],
  "kinds": {"OK": 0, "OOF": 0, "DIRECT_IN": 0, "DIRECT": 0, "GAP": 0, "MULTI": 0}
}
```

**转换规则（架构层已裁决，直接执行，不要再上报）**：

1. **MultiPolygon 拆为多条记录**。依据：`intelligence/world.py:19-24` 的 `Fence`
   为 frozen dataclass，只含单个 `ring`，结构上无法表达多组件；多组件由
   `fences_by_dealer` 表达——此即 main 既有的「亨啡源 split」范式
   （实测亨啡源确为 2 组件，与 main 记录吻合）。
   - `area_id = f"{片区id}#{序号}"`，序号自 **1** 起，**按组件面积降序**
   - **单组件围栏不加后缀**，`area_id` 保持原 `片区id`
   - 所有记录都写 `src_area_id`（原片区id）、`component`、`components_total`

2. **内环存入 `holes`，不得丢弃**。`rings=[外环]` 供 World 消费，
   `holes=[[内环],...]` 保留洞几何。无洞时 `holes: []`。

3. **`area_km2` 按组件面积占比分配 CSV 原值**：
   `area_km2 = 围栏面积 × (该组件面积 / 该围栏全部组件面积之和)`
   —— 避免引入度²→km² 换算常数（仓库内该常数不一致：
   `territory_compile.py` 用 12364.0，`demo_server.py` 用 ≈11415，差 8.3%，本阶段不触碰）。

**消费方约束（已核实 `intelligence/world.py:73-87`）**：
`raw["fences"]` 与 `raw["stores"]` 两键必须存在；`stores` 可为空列表；
`rings[0]` 必须可迭代出 `(lon, lat)` 对。World 会忽略 `holes` 等额外字段。
