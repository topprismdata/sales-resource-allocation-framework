### 围栏 CSV schema（已实测，内联）

表头带 BOM → **必须 `encoding='utf-8-sig'`**。10 个字段：

```
片区id, area_code, 业代组织编码, 围栏名称, layer, 中心点经度, 中心点纬度, 围栏面积, area_level, fence
```

样本行（首行）：
```
片区id     = 694236818
围栏名称   = 晋利泰食品（始兴县）有限公司
中心点经度 = 114.086813      中心点纬度 = 24.818815
围栏面积   = 0.1389
fence      = POLYGON ((114.0834215 24.8319413, 114.0835554 24.8313334, ...))   ← WKT，长度可达数十万字符
```

### ⚠️ 已实测的坑（不处理必然失败）

1. **`fence` 字段超长**：`csv.DictReader` 默认上限 131072，直接读会抛
   `_csv.Error: field larger than field limit (131072)`。
   **必须在读取前执行**：
   ```python
   import csv, sys
   csv.field_size_limit(sys.maxsize)
   ```
2. **坐标系 = GCJ-02**（已实测冻结，见 CONTRACTS §1.1）。
   围栏 CSV 与路网 geojson **同系**，直接比对误差 0.0017m。
   若误判为 WGS84 会产生 **623.8m** 系统位移。
   → `meta.json` 必须声明 `"crs": "GCJ-02"`，**不要在本任务中做任何坐标转换**
   （服务端 `pack_from_disk()` 会在加载时统一转 WGS-84）。

## 输出（必须精确匹配）

### `data/gz/region.json`

```json
{
  "fences": [
    {"area_id": "694236818", "dealer": "晋利泰食品（始兴县）有限公司",
     "area_km2": 0.1389, "rings": [[[114.0834215, 24.8319413], [...]]]}
  ],
  "stores": [],
  "kinds": {"OK": 0, "OOF": 0, "DIRECT_IN": 0, "DIRECT": 0, "GAP": 0, "MULTI": 0}
}
```

字段映射：`片区id`→`area_id`(str)，`围栏名称`→`dealer`，`围栏面积`→`area_km2`(float)，
`fence` WKT →`rings`（**`rings[0]` 为外环**，坐标为 `[lon, lat]` 二元数组列表）。

**消费方约束（已核实 `intelligence/world.py:73-87`）**：
`raw["fences"]` 与 `raw["stores"]` 两个键**必须存在**；`stores` 可为空列表；
`rings[0]` 必须可迭代出 `(lon, lat)` 对。

### `data/gz/meta.json`

```json
{"region_name": "广州", "center": [113.35, 23.05], "zoom": 10, "crs": "GCJ-02",
 "direct_markers": [], "density_assumption_stores_per_km2": 40}
```
