|---|---|---|---|

| 「沿广汕路以北」 | 相对**某条线**取一侧 | `resolve_units` 的"沿"分支只做**街道∩路名交集，无方位** | ⚠️ 能力缺失 |

**本卡聚焦真正的缺陷：静默吞并。**

## 现状（单元库就绪后首次实测，直接采信）

`tools/allocation_ledger.py:36-39`：

```python
core = a["street"].replace("街道","").replace("镇","") if a["street"] else ""
if core:
    self.by_street.setdefault(core, set()).add(a["id"])
    if len(core) >= 2:
        self.by_street.setdefault(core[:-1], set()).add(a["id"])   # ← 截掉末字
```

「凤凰街道」→ core「凤凰」→ **额外注册单字 key「凤」**。

配合 `resolve_units` 的模糊匹配（注意 `k in term` 这个方向）：

```python
hits = set()
for k, v in self.by_street.items():
    if term in k or k in term:
        hits |= v          # ← 无上限累加，无歧义检测，不报错
```

**实测危害**（`data/gz` 真实单元库，6261 单元）：

```
由 core[:-1] 产生的单字 key 共 96 个
  例: ['新','仙','小','正','云','石','派','增','永','荔','九','夏', …]

"大" → 247 个单元      "南" → 245 个单元      "新" → 461 个单元
resolve_units() 全部【静默返回，无任何报错】
```

即：一句「新XX给某商」若打错字或用简称，可能**静默划走 461 个单元**且无人察觉。

对照 pilot 分支纪律：同类场景（"大" 命中 471 条）→ **直接抛错**。

## 实现要求

### 1. 删除单字截断

移除 `core[:-1]` 那两行（`if len(core) >= 2: ... core[:-1] ...`）。
保留 `core` 本身（「凤凰」仍可匹配「凤凰街道」，这是合理简称）。

### 2. 歧义必须报错，不得静默合并

新增异常（**必须继承 `ValueError`**，以复用既有 API 错误通道）：

```python
class AmbiguousTermError(ValueError):
    """术语命中多个不同街道/区/路，拒绝静默合并。"""
```

`resolve_units` 的**模糊匹配分支**（精确匹配分支不受影响）：
- 收集所有命中的 key
- 若命中 key 数 > 1 且它们指向**不同的街道/区/路** → 抛 `AmbiguousTermError`，
  消息须含：原词、命中数量、**前若干个候选名**，并提示「请使用完整名称」
- 若仅命中 1 个 key → 照常返回

> API 层 `tools/demo_server.py:1055-1059` 已捕获 `ValueError` 并转 400，
> 故**无需改动 demo_server**。

### 3. 不得改变的行为

- **精确匹配路径**（`_one` 命中 by_street/by_road/by_district）行为一字不改
- 「沿」语法分支不改
- 方位过滤（质心二分）不改——见本卡开头的修正说明
- 不得改动 `tests/`、`CONTRACTS.md`
