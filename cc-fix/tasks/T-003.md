# T-003 启动可诊断（Phase 2）

规格来源：`cc-fix/CONTRACTS.md`（**只读**）。本卡已内联全部所需信息。

## 目标

让服务**能起来**，并让「起不来」时的报错**指向真正的原因**。

审查认定的问题：数据缺失时回退 `/tmp` 导致报 `FileNotFoundError: /tmp/region.json`，
使用者完全无法从该信息反推出「缺业务数据包」。

**核心原则**：启动阶段只加载启动必需之物；某项能力缺数据，应在**调用该能力时**
明确报错，而不是让整个服务启动失败。

## 现状（已实测）

### 问题 1：`/tmp` 回退（`tools/demo_server.py`，约 111-116 行）

```python
def _resolve_data_dir(data_dir_arg: str | None) -> Path:
    if data_dir_arg:
        return Path(data_dir_arg)
    if (ROOT / "data" / "gz").is_dir():
        return ROOT / "data" / "gz"
    return Path("/tmp")            # ← 删除此回退
```

危害有二：① 报错误导；② 若 `/tmp` 恰有同名文件会**静默加载错误数据**。

### 问题 2：启动期即时构造重对象（`tools/demo_server.py`，约 161-165 行）

```python
STATE = {"pack": _load_pack(_resolve_data_dir(DATA_DIR_ARG)),
         "world": None, "proposal": None,
         "yeidai": YeidaiState(), "yeidai_snapshot": YeidaiState().snapshot(),
         "ledger": Ledger()}
```

`YeidaiState()` 与 `Ledger()` 在**模块顶层**即被构造，各自读取
`{DATA}/basic_units_wgs.json`、`{DATA}/unit_attributes.json`。
这两个文件当前**不存在**（基础单元库，尚未重建），导致服务无法启动——
**即便用户只想看围栏图，与业代/台账功能无关。**

实测当前报错：
```
File "tools/demo_server.py", line 163, in <module>
    "yeidai": YeidaiState(), ...
FileNotFoundError: .../data/gz/basic_units_wgs.json
```

## 实现要求

### 1. 删除 `/tmp` 回退，改为明确诊断

`_resolve_data_dir` 找不到数据目录时，**不要返回任何兜底路径**，
而是打印可操作的中文错误并 `sys.exit(1)`。错误须包含：
① 找过哪个路径；② 缺哪个文件；③ 如何生成（`python3 tools/build_region_pack.py`）；
④ 如何指定其它目录（`--data-dir` / `SRAF_DATA_DIR`）。

`_load_pack` 中 `region.json` 缺失同样处理（当前是裸 `FileNotFoundError`）。

### 2. `YeidaiState` 与 `Ledger` 改为惰性构造

要求：**服务必须能在缺 `basic_units_wgs.json` / `unit_attributes.json` 时正常启动**，
围栏浏览等不依赖它们的功能照常可用；仅当调用业代/台账相关 API 时，
才返回**明确的 JSON 错误**（HTTP 400/503，含缺失文件名与生成方法），
而不是抛栈或 500。

实现方式不限（惰性属性 / 访问器函数 / `functools.cached_property` 等），
但必须满足：
- 模块顶层不再即时构造这两个对象
- 首次真正使用时才加载，加载失败给出可读错误
- **不得改变已有 API 的成功路径行为**

`STATE["yeidai_snapshot"]` 当前也依赖 `YeidaiState()`，一并惰性化。

### 3. 不在本卡范围

- ❌ 不修 RC2.0 引入的 5 个测试回归（另由 T-004 处理）
- ❌ 不重建基础单元库（另行处理）
- ❌ 不改任何业务逻辑
