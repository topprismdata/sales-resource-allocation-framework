## 目标

生成 `basic_units_wgs.json` 与 `unit_attributes.json`——这两个文件是
**台账（Ledger）功能的唯一数据前提**，缺失导致 `/api/ledger_cmd` 等一律返回 503。

它们既不在 `客户数据/`，仓库内也无生成脚本（只被读、从不被写）。
但 `territory_compile.py` 的统一铺盖 `U` 已包含全部所需信息，**可据此导出**。

## 输入：`tools/territory_compile.py` 的模块级数据（import 即可用，实测 6s）

```python
import sys; sys.path.insert(0, 'tools')
import territory_compile as tc
```

可用结构（**已实测确认，勿臆测**）：

| 对象 | 内容 |
|---|---|
| `tc.U` | 6,261 个 4 元组：`(geom, 街道内置名, 街道面名, parent索引)` |
| `tc.U[k][0]` | shapely Polygon，**GCJ-02** |
| `tc.U[k][1]` | 路网 geojson 的 `街道[内置]` 字段值 |
| `tc.U[k][2]` | 所属街道面名（可能为空串） |
| `tc.U[k][3]` | `parents` 索引 `pi` |
| `tc.pdistrict[pi]` | 该 parent 的 `区[内置]` → **区县名** |
| `tc.feats_of(k)` | 该片贴附到的地物名集合（道路/河流名），惰性缓存 |
| `tc.gcj2wgs(x, y)` | 坐标转换函数（经 `intelligence.coords` 引入） |

## 输出

### 1. `data/gz/basic_units_wgs.json`

```json
{"units": [{"geom": "POLYGON ((113.30 23.10, ...))"}]}
```

- **顺序即 id**：第 k 个元素对应 `tc.U[k]`，与 `unit_attributes` 的 `id` 一一对应
- **坐标系：WGS-84**（文件名即契约）。`tc.U[k][0]` 是 GCJ，**必须转换**：
  ```python
  from shapely import ops
  gw = ops.transform(lambda x, y: tc.gcj2wgs(x, y), tc.U[k][0])
  ```
  > 这与 T-006 「不要转换」的情形**不同**——那里 roads 本就是 WGS；
  > 这里 U 是 GCJ 而目标是 WGS，**必须转**。判据始终是「目标文件契约要求哪个系」。

消费方 `tools/allocation_ledger.py:26`：
```python
self.geoms = [shapely.from_wkt(u["geom"]) for u in json.load(...)["units"]]
```

### 2. `data/gz/unit_attributes.json`

```json
{"units": [{"id": 0, "district": "海珠区", "street": "赤岗街道", "roads": ["新港东路","广州大道"]}]}
```

| 字段 | 取值 |
|---|---|
| `id` | `k`（整数，与 basic_units_wgs 的下标一致） |
| `street` | `tc.U[k][1]` 优先；为空则退 `tc.U[k][2]`；仍为空则 `""` |
| `district` | `tc.pdistrict[tc.U[k][3]]` |
| `roads` | `sorted(tc.feats_of(k))` |

消费方 `tools/allocation_ledger.py:24`：`self.attrs = d["units"]`

## ★ 架构层裁决：schema 冲突（已判定，直接执行）

三处对 `unit_attributes.json` 的期望**互相矛盾**：

| 位置 | 期望 | 判定 |
|---|---|---|
| `tools/build_hybrid_attrs.py:68`（**官方生成脚本**） | `json.dump({"units": out}, ...)` | ✅ **权威格式** |
| `tools/allocation_ledger.py:24` | `d["units"]` | ✅ 一致 |
| `intelligence/adjust.py:153-154`（RC2.0 新增） | `for a in attrs:` 当顶层数组 | ❌ **读法有误** |

以官方生成脚本的产出为准 → **格式为 `{"units": [...]}`**。
`adjust.py` 若读到该格式，会遍历到字符串 `"units"` 并在 `a.get("street")`
抛 `AttributeError`。

**处置**：`adjust.py` 的 `_street_district_map()` 增加兼容，**两种格式都能读**：
```python
attrs = json.loads(path.read_text(encoding="utf-8"))
if isinstance(attrs, dict):
    attrs = attrs.get("units", [])
```
这样不破坏任何一方。**不得改动 `allocation_ledger.py` 的读法。**
