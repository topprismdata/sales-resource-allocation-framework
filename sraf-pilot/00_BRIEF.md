## 1. 一句话目标

在 SRAF 已完成的「基础单元分配范式」地基上，补上唯一缺失的一环：

```
一段自然语言描述  →  【本试点要做的：单元筛选】  →  单元 id 集合  →  围栏（天然支持多块）
```

---

## 2. 为什么是这一环（背景）

### 2.1 主线已经发生的事

2026-08-29，SRAF 完成了一次范式切换（见 `docs/FOUR_BOUNDS_RECONSTRUCTION_SPEC.md` §12）：

```
旧: 四至文本 → 导引线 → map matching / min-cut → 边界折线   （复杂、噪声敏感、已证伪）
新: 四至文本 + 中心 → 单元选择 → 单元并集                    （离散、精确）
```

验证结果（作者实测，见 `docs/basic_units_comparison.md`）：

| 单元库 | 单元数 | 经销商中位 IoU | 业代中位 IoU |
|---|---|---|---|
| 官方四级路网 | 2,675 | 0.764 | **0.970** |
| v3 全 OSM 路网 polygonize | 46,420 | **0.969** | 0.769 |

对照：旧的四至文本重建中位 IoU 仅 **0.49**。

### 2.2 已经实现的部分（不要重做）

`tools/yeidai_ops.py` 已实现单元集合范式的**编辑操作**：
- 围栏本体 = 单元 id 集合，几何是派生缓存
- `merge`（并集）/ `split`（邻接图删边→连通分量）/ `transfer_direction` / `delete`
- `@` 提及解析 + 规则优先 + LLM 兜底

### 2.3 缺失的部分（本试点要做的）

规格 §12 明确列为**开放问题**：

> 合同语料如何映射到单元筛选规则（街道名→街道内单元、路名→路侧单元、方向→方位筛选）；
> P2-X 实验设计待定

即：**已有的是「改」，缺的是「从描述生成」。** 两者互补，不重叠。

## 3. 必须知道的坑（这个项目已经付过的学费）

按代价排序。**违反其中任何一条都会让结果失去意义。**

### 坑 1：把「天花板」当成「成绩」报出去 ⚠️ 最高优先级

已发生两次：
- bbox 闭合贡献了大部分 IoU，导致指标长期测量的是错的东西（P1 才发现）
- 亨啡源 IoU 0.897 是**用真值围栏反查边界道路链**得来的（标签泄漏）

**本试点对策**：G3（几何天花板，给定 oracle 规则能否精确复现）与 G4（端到端，
从文字出发）**必须分两张表报，任何情况下不得合并成一个数字。**

### 坑 2：过早给失败编一套理论

2026-08-29 一天之内：08:52 立结论「低保真度主要是手绘噪声」→ 09:35 被自己的 P1
实验推翻 → 13:04 发现真正原因之一是 OSM 只抓了主干道、街巷路根本不在候选集里
（补全后召回率 0.707 → 0.975）。

**本试点对策**：在讨论「算法不行」之前，必须先证明**数据是完整的**。
所有归因结论必须有可复现的数字支撑，写进 JOURNAL 并注明数据条件。

### 坑 3：数据不全被当成算法不行

同上。P2 门禁包含单元库完整性检查，不通过不许进 P3。

### 坑 4：评测语料是循环的

`AGENTS.md` 自述：合同四至文本是**从真值围栏反向提取**的；
2026-08-29 10:08 提交注明「contract text in pack is synthetic」。

**本试点对策**：业务方已明确决定 G4 只用现有合成语料。**这是知情决策，照办**，
但所有 G4 输出必须带 `[合成语料]` 标签，报告中写明局限，不得作为端到端能力对外陈述。

### 坑 5：硬编码绝对路径

`tools/yeidai_ops.py` 与 `tools/component_matcher.py` 里写死了
`/Users/ghb/sales-resource-allocation-framework/...`，在其他机器上无法运行。

**本试点对策**：试点代码一律用「相对仓库根」或 CLI 参数传入的路径，禁止硬编码用户目录。

## 4. 试点范围

| 项 | 值 |
|---|---|
| 地理范围 | 广州市 **海珠区(440105) + 荔湾区(440103)** |
| 单元库 | 官方四级路网 2,675 单元中属于该两区的部分 |
| 主验证线 | **业代片区**（海珠荔湾 02–11，约 10 片）— 数据干净，预期能到 0.95+ |
| 压力测试线 | **经销商围栏**（该区域约 6–8 家）— 官方单元对其只有 0.764，低了不算失败，是 P2b 触发信号 |
| 不做 | 全广州、map matching、UI、修改 SRAF 主线代码 |

选择理由：作者的 `basic_units_comparison.md` 就是用「海珠荔湾 11 片」验证的，
我们的数字可直接对标；且失败案例「穗穗盛」（IoU 0.12）也在此范围内，
密集老城区跑通即证明力最强。
