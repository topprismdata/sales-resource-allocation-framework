## 冻结求值语义（逐条验收）

- `side_of`：候选单元**质心**相对唯一命中线**最近点局部线段切线**的有向侧；不是整线
  首尾走向。`scope` 非空时先求值并严格缩小候选。LineString/MultiLineString 所有 part
  均参与，禁止 `.exterior`。局部线段、八方位向量、叉积与并列顺序严格按 T-503。
- `near`：单元质心到 `center` 的球面距离 `<= radius_km`，只允许复用
  `intelligence.world.haversine_km`；禁止自写换算。
- 线名称解析为精确 → 去后缀 → 包含三级容错；匹配 0 或 >1 一律抛错，禁止两字前缀
  静默兜底。
- 任一含 P5 原语的最终表达式为空必须显式抛错；纯 P3 `minus(X,X)` 仍合法为空。
- 输出 schema 仍恰为 `unit_ids/components/area_km2/rule/warnings`；unit ids 升序唯一，
  components 只在 L1 graph 报告，rule 不变，warnings 恒为 `[]`。

## G5 必含门禁矩阵（缺一即 FAIL）

### A. 继承 G3 的七类退化用例

1. 不存在街道名 → 抛错；
2. 单单元结果；
3. 纯 P3 `minus` 结果为空集；
4. `union` 重复子树幂等；
5. 多分量结果且 `components >= 2`；
6. 街道/区县名称匹配 >1 → 抛错；
7. 至少 3 层嵌套树（根到叶至少 4 层）。

### B. P5 专属用例

- 八方位各一例，至少 8 个独立成功例，四个斜向缺一不可；
- `scope:null` 与 `scope:<非空节点>` 各一例，完整集合必须不同且精确；另测 scope 省略
  与 null 等价；
- 线名 0 匹配与 >1 匹配分别抛错；
- `side_of` 无候选落在请求侧 → 显式抛错；空 scope → 显式抛错；
- `near radius_km=0` 且 center 等于某质心 → 精确单单元；
- `near` 覆盖全区 → 完整 224 uid（真实数据）或合成全 uid，无遗漏/多选；
- 含 P5 的 `minus(P5_NODE,P5_NODE)` → 显式抛错；
- 折线最近段局部切线与整线首尾走向给出不同答案的夹具 → 必须命中局部语义；
- MultiLineString 最近 part 不是第一 part → 必须使用全部 parts；
- OSM part 全部反向后 side_of 集合不变；
- near 必须证明调用 `intelligence.world.haversine_km`，且无坐标转换调用。

八方位可用下列**测试数据表**建立 8 个 subTest；每行 target uid=0、opposite uid=1，
expected 始终手写 `{0}`。所有坐标以 `(113.30,23.10)` 为中心平移小量；`line_delta`
是人工给定的局部切线方向，且与 `target_delta` 垂直：

```python
CASES = [

    ("南",   ( 0, -0.01), ( 0.01,  0)),
    ("东",   ( 0.01,  0), ( 0,  0.01)),
    ("西",   (-0.01,  0), ( 0,  0.01)),
    ("东北", ( 0.01,  0.01), (-0.01,  0.01)),
    ("东南", ( 0.01, -0.01), ( 0.01,  0.01)),

assert set(all_dirs_executed) == {"北","南","东","西","东北","东南","西北","西南"}
```

每行 line 必须以 `center ± line_delta` 手写生成，两个质心为
`center ± target_delta`；expected 不得由 cross/dot 计算。因局部经度缩放，斜向 line 可
轻微偏离严格数学垂直，但夹具需保持足够裕量，禁止把点放在 `1e-12` 边界附近。
