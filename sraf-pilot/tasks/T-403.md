  `sraf-pilot/tests/test_04_nl2rule.py`；不得修改 P1/P2/P3 文件、数据或测试。

## 目标

只用 `oracle_unitsets.json` 的真值 uid 和 `units.json` 的 `street` 属性，反推每条围栏
涉及的正式街道，并生成 21 条中文描述。该方法是“从答案反推输入”，评测存在循环性；
所有 case/CLI/报告下游对象必须携带 `[合成语料]`，不得把它包装成真实合同文本。

本卡只构造并校验内存中的合成 case，不跑 G4 指标、不调用执行器、不调用 LLM、不写报告。

## 输入（相对仓库根；schema 内联）

```jsonc
// data/pilot/oracle_unitsets.json
{
  "method":"3.6-v1.4",
  "link_min_m":50,
  "boundary_centroids":0,
  "fences":{
    "<src_id>":{
      "name":"str","layer":"dealer|yeidai","unit_ids":[0,1],
      "iou":0.97,"recall":0.98,"precision":0.99,"straddle":0,"components":1
    }
  }
}

// data/pilot/units.json
{"crs":"GCJ-02","units":[{"uid":0,"key":"源主键","district_code":"440105","street":"凤阳街道","area_km2":1.0,"centroid":[113.0,23.0],"geom":"<WKT>"}]}

// data/pilot/streets.json
{"streets":[{"name":"凤阳街道","code":"440105014","district_code":"440105","geom":"<WKT>"}]}
```

真实冻结条件：oracle `method == "3.6-v1.4"`、21 条围栏（dealer 4 + yeidai 17）、
每条 `unit_ids` 升序唯一且非空、值域 0..223；L1 单元 224；正式街道目录 40 个，
单元属性实际出现 39 个唯一街道值；2 区县。全程 GCJ-02，不转换。

## 输出 schema 与固定文案

模块内定义并由 T-404 复用：

```python
SYNTHETIC_LABEL = "[合成语料]"
SYNTHETIC_LIMITATION = "本表使用的描述系从真值反推，不代表在真实客户合同上的表现"
RULE_PATH_ONLY_NOTE = "本轮只测试规则路径；未配置、未调用 LLM 兜底"

def build_synthetic_cases(
    oracle_path: Path,
    data_dir: Path,
    *,
    expected_n: int,
    expected_layer_counts: dict[str, int],
) -> list[dict]: ...
```

每条返回对象顶层键精确为：

```json
{
  "label":"[合成语料]",
  "case_id":"G4-001",
  "source":"oracle_unitsets_reverse_streets",
  "layer":"dealer",
  "description":"凤阳街道、华洲街道",
  "oracle_unit_ids":[1,2,8],
  "expected_components":1
}
```

- 不在对象和后续报告中输出客户围栏 `name`；用稳定匿名 `G4-001..G4-021`。
- `oracle_unit_ids` 深拷贝、升序唯一；`expected_components` 原值来自 oracle。
- `label` 必须逐条存在且精确等于 `[合成语料]`；不能只在汇总处标一次。

## 合成算法（冻结；明确承认循环性）

1. 严格校验 oracle 与 units/streets 的上述 schema、调用方给定的 `expected_n` / 分层
   计数、uid 值域和非空性；任一异常中文抛错，不跳样本、不补样本。生产 G4 固定传
   `expected_n=21, expected_layer_counts={"dealer":4,"yeidai":17}`；小型单测必须显式
   传自己的预期计数，禁止通过省略门禁绕过校验。
2. 按 oracle `fences` 的 `src_id` 字符串升序建立稳定 case 顺序，但产物只暴露匿名
   `case_id`；不得把 `src_id/name` 写入 tracked 文件或 stdout。
3. 对每条围栏，直接读取其 oracle `unit_ids`，映射到 raw unit 的 `street` 属性，取唯一
   正式街道名。**禁止调用 `03_dsl.eval_rule/execute` 或任何 NL 解析器反算。**
4. 街道排序按 `streets.json` 的正式目录顺序，不按 uid、围栏几何或执行器结果排序；若
   unit.street 不在正式目录，立即报错。
5. 单街道描述就是正式名。多街道描述用一个连接词连接全部名称；按 case 序号轮换：
   `G4-001=、`、`G4-002=和`、`G4-003=加上`、`G4-004=以及`，之后每 4 条循环。
   不添加区县、方位、道路、坐标或其他从 oracle 无法直接得到的信息。
6. case 只在内存返回；本卡不写 `corpus.json`。T-404 报告写入 gitignored
   `data/pilot/`，不得把客户业务语料提交进 git。

这是有意设计的合成基线，但不是独立测试集：描述由真值 uid 反推，因此后续 Jaccard
只能作为这条受控管线的信息，不能证明真实合同理解能力。

## 硬纪律

- D-2：每个 case 都有标签；任何异常/诊断若按 case 输出，也必须带同一标签。
- D-1：本卡不生成 G3/G4 合并数字，也不读取 G3 结果来影响语料。
- 不读取围栏几何，不用坐标、bbox、IoU、recall、precision 决定描述。
- 不因某条描述可能解析失败而改街道集合、连接词或顺序追求更好分数。
- 不调用 LLM、网络、`03_dsl.execute`、`parse_rule_deterministic`。
- 输入文件和对象只读、不可变；失败不返回半份 21 条结果。
- 不修改冻结文档、JOURNAL、state；不得 commit/push。

## 可执行验收断言

先用 4 个手写 unit、2 条 oracle 围栏、3 个正式街道的临时 JSON 夹具，expected 写字面量：

```python
cases = build_synthetic_cases(
    oracle_path, data_dir,
    expected_n=2,
    expected_layer_counts={"dealer":1,"yeidai":1},

assert len(cases) == 2
assert cases[0] == {
    "label":"[合成语料]",
    "case_id":"G4-001",
    "source":"oracle_unitsets_reverse_streets",
    "layer":"dealer",
    "description":"凤阳街道、华洲街道",
    "oracle_unit_ids":[0,2],
    "expected_components":2,

assert cases[1]["description"] == "南华西街道和华洲街道"
assert all(c["label"] == "[合成语料]" for c in cases)
assert all(set(c) == {
    "label","case_id","source","layer","description",
    "oracle_unit_ids","expected_components",
} for c in cases)
```
