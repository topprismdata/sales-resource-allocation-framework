## 目标

`set[int]`；本卡不计算 `components/area_km2`，不实现 P3b，不引入外部数据或并行。

## 输入（相对仓库根；schema 已内联）

```jsonc
// data/pilot/units.json
{"crs":"GCJ-02","units":[{"uid":0,"key":"源主键","district_code":"440105","street":"街道名","area_km2":1.0,"centroid":[113.0,23.0],"geom":"<Polygon或MultiPolygon WKT>"}]}
// data/pilot/streets.json
{"streets":[{"name":"南石头街道","code":"440105001","district_code":"440105","geom":"<Polygon或MultiPolygon WKT>"}]}
// data/pilot/districts.json（既有顶层键名）
{"streets":[{"name":"海珠区","code":"440105","district_code":"440105","geom":"<Polygon或MultiPolygon WKT>"}]}
// data/pilot/unit_graph.json（T-303 才用于汇总，本卡不得据此改变单元集）

```

真实条件：L1 官方单元 224 个（440105:131 / 440103:93）、40 街道；全程 GCJ-02；
计算量只有 224 单元，保持串行。几何可能是 MultiPolygon，禁止裸用 `.exterior`。

## CONTRACTS v1.5 冻结块（完整内联）

P3-MVP 仅以下四原语：

```jsonc
{"op":"in_street","name":"南石头街道"}
{"op":"in_district","name":"海珠区"}
{"op":"union","args":[<node>,<node>,...]}
{"op":"minus","args":[<node>,<node>]}
```

求值语义逐条冻结：

- `in_street`：用 `units.json` 已落盘的 `centroid` 构造点；严格执行
  `street_geom.contains(Point(unit["centroid"]))`，为真才选中该 uid。禁止按单元面积
  重叠、单元 `street` 属性或单元几何交集来替代求值。
- `in_district`：先解析区县名为唯一区编码，再严格筛选
  `unit["district_code"] == district.code`；禁止几何判定。
- `union`：递归求值所有子节点并取集合并；重复子树天然幂等。
- `minus`：严格为 `eval(args[0]) - eval(args[1])`，不交换参数、不做对称差。
- `side_of` / `near` 属 P3b，本轮不得实现或接受。
- 名称解析：精确 → 去末尾后缀（街道/镇/区）→ 包含匹配；某一级唯一即返回；最终
  0 个或任一级大于 1 个均抛错。禁止静默取首个、两字前缀兜底和跨类型查找。

最终输出契约（由 T-303 汇总，本卡实现不得阻碍）：

```json
{"unit_ids":[12,13],"components":1,"area_km2":3.2,"rule":{"op":"in_street","name":"南石头街道"},"warnings":[]}
```

`unit_ids` 升序唯一；`components` 只在 L1 官方单元层按 `unit_graph.json` 算；`rule`
原样回填；`warnings` 为字符串数组。名称 0 匹配必须抛错，不得返回空集加 warning。

G3 七类退化用例必须全部保留到 T-304：

1. 不存在街道名 → 抛错；
2. 单单元结果；
3. `minus` 为空集；
4. 重复子树 `union` 幂等；
5. 多分量结果且 `components >= 2`；
6. 名称歧义 → 抛错；
7. 嵌套至少 3 层。

G3 必须 100%；expected 必须来自独立字段筛选或人工枚举，禁止调用被测求值器或其
内部 helper 生成 expected。

## 本卡输出与实现纪律

在 `03_dsl.py` 增加一个无副作用递归求值入口（函数名可自解释），输入为已校验的 DSL
树与只读上下文，返回 `set[int]`。不得缓存或回写坐标、几何、解析名或 unit ids 到规则树。

- `in_street` 的测试质心均避开街道边界；真实数据若出现质心恰落街道边界，按上述
  `contains` 结果不选中并原值报告，不得改用 `covers`。
- 递归深度至少支持本卡的 4 层夹具；循环对象虽不可 JSON 序列化，也应被节点校验拒绝
  或以受控中文错误终止，不得无限递归。
- 串行执行；不使用进程池/线程池；不访问网络；不做任何坐标转换。
- 不修改冻结文档、JOURNAL、state，不得 commit/push。

## 可执行验收断言

合成夹具中的 street 多边形、unit centroid、district_code 和 uid 必须由测试手写，
expected 必须是字面量集合，不得通过生产函数算出：

```python
assert eval_rule({"op":"in_street","name":"甲街道"}, ctx) == {0}
assert eval_rule({"op":"in_district","name":"海珠区"}, ctx) == {0, 1}
assert eval_rule({
    "op":"union",
    "args":[{"op":"in_street","name":"甲街道"},
            {"op":"in_street","name":"乙街道"}],
}, ctx) == {0, 2}
assert eval_rule({
    "op":"minus",
    "args":[{"op":"in_district","name":"海珠区"},
            {"op":"in_street","name":"甲街道"}],
}, ctx) == {1}
assert eval_rule({
    "op":"union",
    "args":[{"op":"in_street","name":"甲街道"},
            {"op":"in_street","name":"甲街道"}],
}, ctx) == {0}
assert eval_rule({
    "op":"minus",
    "args":[{"op":"in_district","name":"海珠区"},
            {"op":"in_district","name":"海珠区"}],
}, ctx) == set()
```

另写一棵至少 4 层（根到叶）的人工 DSL 树并将 expected 写成字面量 uid 集；断言求值前后
`json.dumps(rule, sort_keys=True)` 完全一致。用同坐标但不同单元几何面积的夹具证明
`in_street` 只看质心；用 district 几何刻意错位的夹具证明 `in_district` 只看属性。

真实数据的独立交叉断言至少包含：

