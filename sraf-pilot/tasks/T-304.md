## CONTRACTS v1.5 冻结块（完整内联）

P3-MVP 只允许：

```jsonc
{"op":"in_street","name":"南石头街道"}
{"op":"in_district","name":"海珠区"}
{"op":"union","args":[<node>,<node>,...]}
{"op":"minus","args":[<node>,<node>]}
```

冻结语义：

- `in_street`：严格执行 `street_geom.contains(Point(unit["centroid"]))`；不用面积重叠。
- `in_district`：`unit.district_code == 唯一区编码`；不用几何。
- `union`：所有子结果集合并；重复子树幂等。
- `minus`：`eval(args[0]) - eval(args[1])`。
- `side_of/near` 是 P3b，本轮拒绝。
- 名称解析：精确 → 去末尾后缀（街道/镇/区）→ 包含匹配；唯一才成功；0 个或
  大于 1 个均抛错。禁止静默首个、两字前缀兜底、跨类型匹配。

输出 schema 精确为：

```json
{"unit_ids":[12,13],"components":1,"area_km2":3.2,"rule":{"op":"in_street","name":"南石头街道"},"warnings":[]}
```

`unit_ids` 升序唯一；`components` 只用 L1 `unit_graph.json` 诱导子图；空集 components
为 0；`area_km2` 是所选 L1 单元字段之和；`rule` 原样；成功的 MVP `warnings=[]`；
名称失败抛错，不得伪装为 warning。

G3 七类必含退化用例，缺一即本卡失败：

1. 街道名不存在 → 抛错，不返回空集；
2. 单单元结果；
3. `minus` 结果为空集；
4. `union` 含重复子树，结果幂等；
5. 多分量结果，`components >= 2`；
6. 名称匹配歧义（大于 1）→ 抛错；
7. 嵌套至少 3 层的树。

通过线：所有应成功用例 `actual_unit_ids == expected_unit_ids`，且所有应失败用例抛出
指定契约异常；**100% 或 FAIL，没有接近即可。**

## 防循环论证：expected 的唯一允许来源

本节是 G3 有效性的硬门禁：

1. 合成小样本：测试先手写 units、街道/区县面、graph，并将 expected uid 集写成
   **字面量**（如 `{0, 3}`）。不得调用 `eval_rule`、`execute`、名称解析器、生产
   components helper 或它们的包装函数生成 expected。
2. 真实区县：expected 直接从原始 `units.json` 做
   `unit["district_code"] == "440105"/"440103"` 筛选；区编码是本卡固定常量，
   不通过生产名称解析器取得。
3. 真实街道：expected 直接从原始 `units.json` 做
   `unit["street"] == <卡内写死的正式街道名>` 筛选；生产执行器仍必须按街道**几何
   包含质心**求值，禁止偷换为该属性筛选。
4. expected components 若需比较，由测试文件内独立的最小 BFS 按 raw adjacency 与
   expected uid 字面量/独立字段筛选结果计算；不得调用生产 components helper。

禁止先跑执行器再把结果抄成 expected，禁止用 actual 的长度/内容构造 expected，禁止只
验证自洽或 schema。该规则专门防止 bbox 掩盖信号与 IoU 0.897 反查式自证重演。

> 上一轮 G3 FAIL（uid=214）**是契约缺陷被正确捕获，不是你的实现错误**，不计失败。

## 变更内容

`in_street` 的求值语义由**几何判定**改为**属性判定**：

```python
# 旧（v1.6，已废弃）：单元质心落在街道多边形内
sel = {i for i,u in enumerate(units) if street_polygon.covers(centroid(u))}

# 新（v1.7）：单元 street 属性精确等于解析后的街道名
sel = {i for i,u in enumerate(units) if u["street"] == resolved_street_name}
```

**街道多边形几何只用于名称解析**（用户文本 → 规范街道名），**不参与单元选取**。
`in_district` 不变（本来就是属性判定）。

## 变更原因（实测数据）

| | 几何语义 | 属性语义 |
|---|---|---|
| 与属性不符的单元 | **10 / 224（4.5%）** | — |
| 质心不落在任何街道内 → DSL 永远选不到 | **uid=43** | 无 |
| `union(全部 40 街道)` 覆盖 | **223/224 ❌** | **224/224 ✅** |
| 与 `in_district` 判据一致 | ❌ | ✅ |

典型：uid=214 面积 2.59 km²，横跨琶洲 56.6% / 官洲 43.4%（骑跨单元），
厂商 `street` 属性定为「官洲街道」。**街道归属是业务事实，不该被质心启发式覆盖。**
