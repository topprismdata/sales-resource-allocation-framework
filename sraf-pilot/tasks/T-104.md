# T-104 — P1 坐标系数字验证

## 状态与依赖

- 阶段：P1
- 依赖：T-102、T-103 完成；G0 经 L0 签字。
- 后继：T-105。
- 解冻裁定：使用全部 4 条经销商围栏，每条顶点等距抽样至多 200 点；距离函数只复用
  `intelligence.world.haversine_km`，坐标转换只复用 `intelligence.coords.gcj2wgs`；
  单元几何始终不转换。A 为围栏原坐标、B 为围栏转 WGS 后分别到最近单元边界的距离
  中位数；A < 100m 且 B > 300m 才判同为 GCJ-02；证据写 `crs_evidence.json`。
- 施工范围：只允许增量修改 `sraf-pilot/src/01_extract.py` 与 `sraf-pilot/tests/test_01_extract.py`。

## 目标

用数字证据验证客户经销商围栏与官方单元边界是否同为 GCJ-02。必须分别得到“GCJ 原坐标直比”
与“按 L0 确认方式转 WGS 后混合对比”的最近距离中位数，不能以“客户 CRM 应该是高德系”代替测量。

## 输入（相对仓库根）

- `data/pilot/units.json`

```json
{"crs":"GCJ-02","units":[{"uid":0,"key":"...","district_code":"440105","street":"...","area_km2":1.0,"centroid":[113.0,23.0],"geom":"<WKT>"}]}
```

- `data/pilot/fences_dealer.json`

```json
{"fences":[{"name":"...","src_id":"...","area_km2":1.0,"center":[113.0,23.0],"overlap_ratio":0.999,"geom":"<WKT>"}]}
```

- 样本固定为试点输出内全部经销商围栏，必须 `n_fences == 4`，不抽围栏。
- 每条围栏按顶点序列确定性等距抽样至多 200 点；少于或等于 200 时用全部顶点。
- 参考边界为 `units.json` 中全部 224 个试点单元的边界。每个样本点取到全部单元边界
  的最小距离；将该最小距离对应的边界最近点坐标交给
  `intelligence.world.haversine_km` 换算为公里再乘 1000。禁止自写经纬度换算。
- 对照 A：围栏顶点保持原坐标；单元几何保持原样。对照 B：只对围栏顶点调用
  `intelligence.coords.gcj2wgs`；单元几何仍保持原样。禁止另写转换公式。
- 每条围栏分别计算 A/B 距离中位数；总 `median_A_m`/`median_B_m` 对全部样本点计算。
- 判定式只能是 `median_A_m < 100 and median_B_m > 300`。满足则
  `SAME_CRS_GCJ02`；否则 `INCONCLUSIVE`，不得下坐标结论，必须输出
  `ESCALATION:<A/B数值>` 并停止。

# 【L0 修订 · 2026-08-30 06:20 · 契约 v1.3】判定式变更，须重跑

> 本节由 L0 直接追加（原因：判据缺陷是 L0 的设计错误，且已写入 CONTRACTS v1.3）。
> **与上文冲突时以本节为准。** 上一轮 L2 的 `[GATE-FAIL]` 行为正确，不计失败。

## 变更原因

v1.2 判据 `median_A < 100m AND median_B > 300m` 中的 **B 条件结构上不可达**：

「到最近边界的距离」是**饱和度量**——无论把点位移多远，它到*最近*边界的距离
都不超过约半个格子。实测：

| 量 | 值 |
|---|---|
| `gcj2wgs` 真实位移量中位数 | **623.2 m** |
| 单元面积中位数 | 0.322 km² → 等效边长 567 m |
| 最近边界距离理论上限（半格） | **284 m** |
| 上一轮实测 median_B | 118~237 m ← 饱和 |

阈值 300m 在 284m 天花板之上，永远达不到。

## 新判定式（替换原判定式）

新增第三个量 **C = `gcj2wgs` 在这批顶点上的位移量中位数**（不是到边界的距离，
是顶点自身位移前后的距离）。

```
median_A < 1.0 m                  判据①  共配准：顶点级重合
AND 500.0 <= median_C <= 750.0    判据②  转换自检：位移量符合 D13 广州 ~623m
→ verdict = "SAME_CRS_GCJ02"，退出码 0

否则 → verdict = "INCONCLUSIVE"，写 [GATE-FAIL]，非零退出，不得下结论
```

**B 保留计算并落盘，但不再参与判定**（记录性指标，供诊断网格密度）。

## 新 crs_evidence.json schema（替换原 schema）

```jsonc
{"method":"3.5.4-v1.3","n_fences":4,"vertex_cap":200,
 "median_A_m":0.0,
 "median_B_m":0.0,
 "median_C_disp_m":0.0,
 "unit_median_area_km2":0.0,
 "grid_half_cell_m":0.0,
 "verdict":"SAME_CRS_GCJ02",
 "per_fence":[{"src_id":"...","name":"...","n_vertices":200,
               "median_A_m":0.0,"median_B_m":0.0,"median_C_disp_m":0.0}]}
```

`grid_half_cell_m` = `sqrt(median(unit.area_km2)) * 1000 / 2`

## 新验收断言（替换原判定相关断言，其余断言不变）


## 实现提示

- C 的算法：对每个采样顶点 `p`，`q = gcj2wgs(p[0], p[1])`，
  距离 = `haversine_km(p, q) * 1000`，取全体中位数
- 仍禁止自写换算公式；C 同样复用 `haversine_km` / `gcj2wgs`
- **几何类型注意**：围栏可能是 `MultiPolygon`，取顶点时不能直接用 `.exterior`，
  需先展开 `geoms`（L0 实测踩过此坑）
- L0 已独立复算：A≈0.0016m、C≈623.2m、半格≈284m。你的结果应与此一致
