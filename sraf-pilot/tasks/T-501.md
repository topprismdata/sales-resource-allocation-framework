## 目标

从 L0 已准备的 OSM Overpass JSON 快照构建 P5 唯一线要素输入
`data/pilot/lines.json`。必须读取快照中的全等级 `highway/waterway/railway`，不得调用
网络，不得复用或改写主线 `tools/fetch_region_osm.py` 的查询；该主线查询只取
motorway～secondary 且强制 `name`，在试点区仅覆盖约 12.8% 路网
（45,772 条中约 5,851 条），是已知错误数据边界。

本试点业务数据和 L1 单元均为 GCJ-02，OSM 原始坐标为 WGS-84。每个 OSM 坐标入库前
必须且只能调用一次 `intelligence.coords.wgs2gcj(lon, lat)`；禁止复制、改写或近似坐标
转换公式，禁止把 OSM WGS-84 原值写入 `geom`。

## 输入（schema 内联）

输入路径必须由 CLI `--src` 显式传入；L0 当前已准备的只读快照为
`/tmp/p2b_probe/osm_raw.json`。仓库内路径一律按仓库根相对寻址。

```jsonc
{
  "version": 0.6,
  "generator": "Overpass API ...",
  "osm3s": {"timestamp_osm_base": "...", "copyright": "..."},
  "elements": [
    {
      "type": "way",
      "id": 25680240,
      "geometry": [
        {"lat": 23.0442309, "lon": 113.2995144},
        {"lat": 23.0441725, "lon": 113.2995322}
      ],
      "tags": {
        "highway": "secondary",
        "name": "如意一马路"
      }
    }
  ]
}
```

冻结事实：快照含 45,772 条 `highway/waterway/railway` way，其中 13,945 条具有
非空 `tags.name`。这些数字用于固定快照的真实 smoke 验收，不得重新发查询“校准”数据。

## 输出 schema（P5 卡载冻结；L2 不得自行改字段）

```jsonc
// data/pilot/lines.json
{
  "schema_version": "p5-lines-v1",
  "crs": "GCJ-02",
  "source_crs": "WGS-84",
  "source_sha256": "<输入文件原始字节 sha256，小写 64 位十六进制>",
  "counts": {
    "source_elements": 45772,
    "source_named_ways": 13945,
    "output_names": 1234,
    "output_parts": 13945
  },
  "lines": [
    {
      "name": "华南快速",
      "classes": ["highway"],
      "osm_way_ids": [123, 456],
      "geom": "MULTILINESTRING ((...))"
    }
  ]
}
```

字段规则：

- 顶层与每行字段集合必须恰与上面一致，不得加入 bbox、别名、推断等级或业务数据。
- 只处理 `type == "way"` 且 `tags.name` 为去首尾空白后非空字符串的元素；元素还必须
  至少具有 `highway/waterway/railway` 三键之一。未命名 way 计入 `source_elements`，但不
  进入 `lines`；禁止用 `name:zh/name:en/ref` 冒充 `name`。
- 同一个精确 `name` 的 way 聚合为唯一一行；不得把同名 way 误报为名称解析歧义。
- `classes` 是该名称所有 way 命中的 `highway/waterway/railway` 键名之升序唯一数组；
  `osm_way_ids` 升序唯一。
- 每个 way 的 `geometry` 按 OSM 原始点序形成一个 LineString part；同名多 way 形成
  MultiLineString。单 way 可写 LineString。`geom` 只允许非空 LineString/MultiLineString，
  每个 part 至少 2 个不同点；不得 polygonize、buffer、union/difference 或访问
  `.exterior`。
- `lines` 按 Unicode `name` 升序；同名 parts 按 `osm_way_id` 升序；坐标点序保持 OSM
  原顺序。JSON 使用 UTF-8、`ensure_ascii=False`、稳定缩进并以换行结尾。
- `counts.output_names == len(lines)`；`counts.output_parts` 等于所有输出行的 way/part 数；
  固定快照上 `source_elements == 45772`、`source_named_ways == 13945`、
  `output_parts == 13945`。
- 任一命名 way 缺失/非法 id、几何少于 2 个不同有限坐标、转换结果非有限值，整次构建
  中文抛错且不得留下半份输出；不得静默跳过脏命名 way。

## P5 三条冻结约束（不得打折）

1. `side_of.dir` 必须支持八方位：北、南、东、西、东北、东南、西北、西南。快速实验
   四方位 0.6765、八方位 0.7931，差 0.12，斜向不可省。
2. 表达式组装/优选必须至少保留一项：若结果为空必须显式抛错，不得静默返回空集。
   本卡不实现组装器，但数据 schema 不得引入“缺线时返回空结果”的降级行为。
3. `side_of` 不能解决只占街道 6.7% 级别的小片区；该边界留给 P6 细面。本卡不得通过
   删线、道路等级过滤、buffer 或调参制造虚假高分，低分案例后续如实报告。

## 本卡输出与实现纪律

- 提供可单测的纯构建函数与 CLI：
  `python3 sraf-pilot/src/05_lines.py --src <OSM_JSON> --out data/pilot/lines.json`。
- 输入只读；先在内存完整校验与构建，再同目录临时文件原子替换目标。失败时目标原文件
  字节不变；不得修改输入快照。
- 只导入并调用 `intelligence.coords.wgs2gcj`；不得调用 `gcj2wgs`、`convert` 或主线 pack
  转换器，不得二次转换。
- 不访问网络，不调用 `tools/fetch_region_osm.py`，不生成 Overpass 查询，不修改冻结文档、
  JOURNAL、state，不得 commit/push，不得调用 omp。
