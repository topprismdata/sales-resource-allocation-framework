# 四至重建 Oracle Ladder 实验结果（2026-08-29）

纯几何评价（不使用门店）。屏障语义：四条地标线带（200m）→ 150–330m 栅格 →
从合同中心点 BFS 连通分量。真值 = 客户手绘围栏（GCJ→WGS 归一后）。
脚本：`tools/bench_oracle_ladder.py`。

## 阶梯

| 档 | 语义 | IoU 中位 | ≥0.5 | ≥0.7 | ≥0.8 | 泄漏 |
|---|---|---|---|---|---|---|
| 旧实现 | anchor+clip+corner 缝合矩形环（oracle 半径） | 0.069 | 0 | 0 | 0 | — |
| V1 | 按合同名查线（含区界 admin 层修复）+ 屏障 BFS | **0.249** | 5 | 3 | 1 | 37/38 |
| **V1c** | V1 + 外接框闭合（oracle closure） | **0.493** | **17** | 3 | 2 | 37/38 |
| V2 | 作弊选弧：任意 OSM 线贴真值边界 + BFS | 0.187 | 0 | 0 | 0 | 37/38 |
| V3 | V2 + 外接框闭合 | 0.453 | 12 | 0 | 0 | 37/38 |

## 三个决定性发现

1. **闭合是第一大杠杆：0.249 → 0.493（×2），不需要任何新合同信息。**
   37/38 泄漏 = 四条屏障几乎从不首尾相接。这正是简报 Q4 的预言：open-barrier
   BFS 的泄漏是语义上的必然，不是随机 bug。工程解法 = 端点吸附 + 最小代价桥接 +
   闭环搜索（vector graph），可把"闭合"从 oracle 变成算法。
2. **实体/弧线选择不是瓶颈：V2（oracle 贴真值选任意线）反而比 V1 差
   （0.187 < 0.249），V3 也不如 V1c（0.453 < 0.493）。**
   合同点名的地标本身就是最优屏障——名字匹配已经够好，往"更贴真值的任意线"
   优化是错方向（引入支路噪声）。OSM 配对/命名歧义被从高优先级剔除。
3. **闭合后天花板 ≈ 0.49–0.55，且两极分化（2 家 ≥0.8，多数卡在 0.4–0.5）。**
   剩余误差 = 手绘偏移 + 凹形/多块表达力（简报定理一/二）。要破 0.7 必须加
   合同槽位：弧段起终点、boundary_mode/offset、include/exclude、component
   结构——且只对"闭合后仍差"的那批合同定向补要，不是全量。

## 对简报三分类的判定

- **实现 bug**：admin 层未接（已修，+0.096）；不闭合（占最大单项，可纯算法修）
- **四至信息上限**：V1c ≈ 0.49 就是当前四至（4 线+1 点）+完美闭合的实证上限
- **需新槽位**：从 0.49 到人工水平的差额部分（凹形/多块/偏移无规律者）

## A2 忠实度测量（人工边界 vs 名义地标）

人工围栏周长被其四至名义地标（含区界层）覆盖的比例：
- 容差 150m：中位 **30%**，0/38 达到 80%
- 容差 1500m：中位 **45%**，仅 2/38 达到 80%

判定：**人工围栏的边界大部分长度（>55%）并不落在合同四至地标上**。两种成分：
(a) 合同外的手绘细节（沿其他道路、历史调整、切角——业务现实）；
(b) 我们的名义地标几何不全（OSM 断链、admin 碎片缺段）。
区分 (a)/(b) 是 case 级人审问题，不是算法问题。这给 0.49 天花板的解释补上
了最后一块：即使完美闭合，四至也只约束了人工边界的一半——IoU≈0.5 恰好对应
"四至约束的那一半全对、自由的那一半平均半对"。
