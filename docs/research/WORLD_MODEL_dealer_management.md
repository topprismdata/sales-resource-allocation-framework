建模立场：**Model Reality, Not Systems**——建模真实世界实体，不镜像数据库表结构。

## 1. 为什么需要世界模型

智能 = 世界模型 + 在其上的推理（arXiv:2411.14499 双功能）。现状两个世界模型都不够：

| 世界模型 | 覆盖 | 缺失 |
|---|---|---|
| visit 排班引擎 | 客户/坐标/频次/容量/日历 | 合同、主体、围栏语义、供应、市场 |
| SRAF 01 规范 | 抽象本体架构 | 经销商管理领域的实例化 |

本对话积累的领域发现（三层围栏、85% 上游一致率、连锁直供、卖断条款）散落在分析文档中，本文收编为统一本体。

## 2. 本体分层（UFO 对齐）

```text
L1 对象层（endurants，可识别可延续的"东西"）
   LegalEntity        法人主体（统一社会信用代码标识；GLN 兼容）
   OrgUnit            组织单元（大区/城市/经销商内部团队；
                      层级镜像组织原则：决策层级=组织层级）
   ServiceLocation    售点（位置、渠道、营业状态；GLN 模式外部 ID）
   MarketFeature      市场要素（行政边界、道路、河流、竞品体系）
   Product            品项（GTIN 兼容标识）

L2 角色与承诺层（UFO-C，社会建构）
   DealerRole         经销商角色【角色，非种类】——LegalEntity 承担
   SalesRepRole       业务代表角色——两种归属：厂家业代（厂家发薪
                      协管终端）/ 经销商业务员（经销商发薪）；
                      由 OrgUnit 的人员承担
   Contract           合同 = 承诺/义务结构（授权范围、期限、
                      条款"卖断式销售+无理由不退换"= 典型 commitment）
   TerritoryDesign    围栏设计（F1 合同围栏 + F2 运营围栏，见 §3）
   Beat               业代线路【Layer-B 设计对象】：定点→定片→定人
                      →定频→定线的产物；线路=对门店的拜访承诺（PJP）
   CoveragePolicy     拜访频率政策（ABC 分级：A 周访/B 两周/C 月访）

L3 事件层（perdurants，在时间中展开）
   SupplyEvent        供应事件（EPCIS ObjectEvent 模式：发货/收货）
   LifecycleEvent     生命周期事件（开店/关店/续签/退出）
   FenceChangeEvent   围栏变更事件（提案/审批/生效）
   IdentityEvent      身份事件（08 八场景：合并/拆分/搬迁/更名）

L4 派生观察层（quantities/observations，由 L3 计算）
   SupplyFootprint    供货足迹 F3（事件流的物化视图）
   AlignmentMeasure   三层对齐度 align(F1,F2,F3)
   CoverageGap        覆盖缺口（诊断的原始信号）
```

关键规则：L4 一切均可从 L3 事件流重算（可重放）；L2 角色可授予/撤销而 L1 主体恒在。

## 2A. 三级独立决策层（v2.1 核心——层级镜像组织，层间仅接口交接）

行业基本盘：组织层级决定决策层级。三级分配各自独立，**禁止跨层干预**：

```text
Layer-D 经销商区域层（已建：dealer_territory + 本世界模型）
  决策主体: 厂家城市经理（分片包干制：市场→经销商网格）
  输入:     合同/围栏/市场要素/门店全集
  输出:     store → dealer 归属（+身份解析状态）     ← 接口 I-D
  独立评估: 三层对齐 align(F1,F2,F3)、区域公平

Layer-B 业代线路层（缺失，待建）
  决策主体: 经销商老板+主管（厂家督导协访纠偏）
  输入:     I-D 给定的本经销商门店清单（视为固定）
            + 业代名册 + 承载力（K-BENCH-003）
  输出:     store → beat → 业代 归属 + CoveragePolicy 频率 ← 接口 I-B
  独立评估: 负荷均衡（Σ店数×频率）、片区紧凑度、达成率
  方法:     定点→定片→定人→定频→定线；线路四原则：
            片区化/分级频率/负荷均衡/固定化（客情）

Layer-V 拜访排程层（visit 引擎，只读依赖）
  决策主体: 业代/排程系统
  输入:     I-B 给定的线路+频率（视为固定）+ 日历/容量
  输出:     拜访计划（哪天/哪家/顺序）
  独立评估: 频次合规、旅行时间、容量利用

层间纪律（用户拍板：每一层独立，不要干扰）:
  1. 上游输出 = 下游给定值；下游发现问题→向上游发信号，不自行越权改
  2. 各层优化目标互不掺和：D 层不优化排线效率；V 层不管围栏/线路
  3. 各层独立评估、独立审批；诊断先定位层，再在该层内归因
  4. 同一世界模型，三层各取 slice——本体统一，视图分权
```

## 3. 三层围栏的本体地位（v2 核心升级）

```text
F1 合同围栏   规范性社会对象（UFO-C）：因合同文本而存在，
              多为非几何描述（"某某路以东"），F1→几何需解释行为
F2 运营围栏   人工制品（designed artifact）：系统 polygon，可干预
F3 供货足迹   派生观察量（L4）：供应事件流的物化视图，纯观察
```

- 对齐度 align(F1,F2,F3) 是**三个本体层级间的测量**：规范 vs 设计 vs 实际
- 85% 上游一致率 = F2 内 85% 门店的 F3 归属围栏经销商，为正常值（E7 直供与跨界采购导致 100% 不可达）
- F1→F2 是解释行为（记录解释证据）；F2→F3 偏差是诊断信号

## 4. OntoClean 检查记录（v1 错误修正）

| v1 设计 | 问题 | v2 修正 |
|---|---|---|
| "Dealer" 作为实体种类，带生命周期状态 | -R（非刚性）："经销商"可来去而公司恒在；同一公司可兼任零售 | DealerRole 归入 L2，作为 LegalEntity 承担的角色；active/constrained 等状态是**角色承担的状态**，不是主体的状态 |
| E6 SupplyEdge 静态边（dealer→store） | 供应本质是事件流；静态边丢失"何时/何批/何品项"且无法追溯 | SupplyEvent（L3，EPCIS 模式）；"供应关系"为 L4 派生视图 |
| Contract 建模为普通实体 | 合同的本质是承诺/义务束（UFO-C），条款即 commitment | Contract 为承诺结构：授权承诺、排他义务、退换条款各自独立可追溯 |
| Territory 大类含三围栏 | +I 失败：三种围栏标识方式不同 | 拆为 TerritoryDesign（L2 设计对象）+ SupplyFootprint（L4 观察量） |

## 5. 供应关系 = 事件流（EPCIS 模式）

```text
SupplyEvent:
  event_id, event_type(_objectEvent)
  what:    GTIN 品项 + 数量
  when:    valid_time（业务时间）
  where:   发货方 GLN / 收货方 GLN（对应经销商仓 / 售点）
  why:     businessStep（CBV 词汇：shipping / receiving）
  how:     disposition（in_transit / delivered / sold）
  + 证据等级：POS 流水 HIGH / 业务员上报 MEDIUM / 推断 LOW
```

- 供货足迹 F3 = 时间窗口内 SupplyEvent 聚合的物化视图，**可随时重算**
- 二级销售（经销商→门店）对应 SCOR Deliver 流程；一级销售对应 Source
- 本对话数据中的"门店上游"判定即从事件流聚合而来，非人工指定

## 6. 双时间线操作化（XTDB/Graphiti 模式）

所有事实四元组：`(fact, valid_time, transaction_time, evidence)`

三条操作规则（v2 新增，来自双时间线 KG 实践）：

1. **非破坏性版本化**：事实变更 = 关闭旧记录（打 `invalidated_at`）+ 开新记录；历史永不覆盖
2. **时间点查询**：任意 (valid_t, as_of_t) 组合可查询"当时系统所知的世界"——诊断 7 月缺口时只允许用 as_of ≤ 7 月底的数据（杜绝时光机倒错）
3. **矛盾登记簿**：冲突事实（两个上游并存）不裁决不丢弃，登记后交 08 身份规则或人工处理——系统不得幻觉出单一"正确"状态

## 7. 因果结构（智能层推理骨架）

世界模型双功能（arXiv:2411.14499）→ 两种推理引擎：

```text
可干预:  F2 运营围栏、拜访频次、经销商资源投放、合同条款（谈判）
观察:    F3 供货足迹、对齐度、缺口、销量
背景:    地理位置、河流道路、竞品与连锁决策、季节
```

- **诊断**（理解现状）：缺口 ∈ {缺资源 | 缺身份 | 缺通路（直供） | 缺意愿}
- **预测**（模拟未来）：干预 F2/资源 → 模拟 F3 与销量响应
- **建议**：可干预变量上搜索，目标函数来自 06 指标，结论带证据链与等级

## 10. 最小可用实例（Vertical Slice v0）

数据基础：`/tmp/gz_data.json`（38 围栏 + 33,109 门店 + kinds 分类）。门店字段：`n`名称/`c`渠道/`d`区县/`u`上游单位/`lon,lat`/`direct`直供标志/`dealers`供应商列表/`kind`六分类。**渠道结构：食杂店/批发 51%、特殊渠道 33%、CVS 11%——典型批发分销市场。**

`kind` 字段 = 数据侧已存在的 L4 物化视图（与本文概念对齐）：

```text
OK        26,182 (79%)  三层对齐正常（F2 内 F3 归属围栏经销商）
OOF        4,300 (12%)  F2→F3 偏差（跨界供货，诊断信号）
DIRECT_IN  2,111  (6%)  直供（缺通路类，不进缺口候选）
GAP          433  (1%)  覆盖缺口（诊断的原始信号）
DIRECT        76        直供店
MULTI          7        矛盾登记簿真实实例（多上游并存）
```

直供上游验证：美宜佳系 2,127 家（占直供店 97%），华润万家 57、沃尔玛 7——**印证 E7 连锁直供是结构性现象而非个案**。

先回答三问：

1. **这个围栏健康吗** → align(F1,F2,F3) 三层对齐报告
2. **这个缺口属于哪类** → 四分类诊断（资源/身份/通路/意愿）
3. **调整 X 影响谁** → E6 影响传播查询

验收：三问在真实数据上可复现回答，每答案带证据链（事实×双时间×等级），且 L4 可从事件流完整重放。

## 备选方案与取舍

- **A. 不建世界模型，04 硬编码规则**：不可扩展、规则打架、无法追溯。否决。
- **B. 直接上图数据库（Neo4j）**：本体贴合但基建重。**取舍：dataclass + JSON 快照落地，接口按图模型设计；双时间线参照 XTDB 的 close-and-open 语义在应用层实现。**
- **C. 完整 gUFO/OWL 形式化**：学术严谨但落地成本高。**取舍：本体设计遵循 UFO 概念区分（本文档已做），实现用轻量 dataclass，未来需要互操作时映射 gUFO。**

## 拍板结果（2026-08-28）

1. **F1 几何化**：✅ 接受"文本 + 人工解释的几何代理"，解释误差记录在证据中，解释过程可追溯（谁/依据/何时）。
2. **供应事件源**：⏸ 保守默认执行——POS 按月可得性未确认，供应边证据上限暂标 MEDIUM；业务确认后可升 HIGH。**唯一遗留项。**
3. **存储选型**：✅ JSON/SQLite 起步 + 图接口预留 + 应用层双时间线（XTDB close-and-open 语义）。
4. **直供识别**：✅ **关闭**——门店主数据自带 `direct` 标志与 `kind` 六分类（§10 已验证），字段基础现成，无需新口径。
5. **角色建模深度**：✅ v0 只建 DealerRole；分公司/仓库角色出现混淆场景再加。
