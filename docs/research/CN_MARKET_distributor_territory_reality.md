# 中国市场经销商区域分配现实 — 对 SRAF 的设计输入

**状态：** 分析报告（非规范性文档）  
**日期：** 2026-08-27  
**触发：** 老板指出——中国市场实际更多是**经销商区域分配**，一般用不到算法。  
**用途：** 修正 SRAF 工程方向的第一个输入。结论需要老板拍板后再变成代码。

---

## 1. 现实形态：经销商区域是合同，不是优化问题

中国快消/饮料市场的"区域分配"，主体是**厂商 ↔ 经销商的合同边界**：

```text
分配的形式：
    合同条款划定的经销区域（独家/总经销/分渠道）
    粒度 = 行政区 / 街道 / 批发市场 / 商圈，甚至按渠道拆分
    （餐饮渠道一家、流通渠道一家、KA 直供）

分配的驱动因素：
    历史渊源（谁先做起来的、父传子）
    经销商能力（资金、仓储、车队、业代人数、客情）
    厂家渠道策略（精耕 vs 大流通；直营与经销的边界）
    区域潜力与增长承诺（年度合同里的销量任务）
    窜货与价格体系的管控需要

分配的变更：
    极低频（合同年度为周期；中期极少动）
    极高成本（库存交接、客情赔偿、过渡期市场波动、团队动荡）
    决策人 = 渠道总监/老板拍板，不是模型算出来的
```

**推论：把"平衡聚类 + 局部交换"这类 territory optimizer 当作 SRAF 的核心交付，
在中国市场是伪需求。** 书（Zoltners Ch8）的 territory alignment 方法论对应的
是欧美 DSD（厂商直营门店覆盖）语境；中国语境里"区域"的分配主体是
经销商，覆盖执行外包给经销商，厂家管的是合同、能力与秩序。

这不是书错了——书 Ch4 本身就讲了 Hershey/Mars 对 food broker 的不同用法，
即「渠道结构决定 sales force 设计」。只是我们的 MVP 选错了起点。

## 2. 对既有规范的对照：哪些适用、哪些要重新定位

| 规范内容 | 中国经销商语境下的判定 |
|---|---|
| 01 `Account/Prospect/ServiceLocation` | **适用**：门店洞察仍是底座（RTM/拜访仍在） |
| 01 Actor 里的 `Distributor`、`Organization` | **适用但太薄**：需要升级为「合同区域条款」的承载对象 |
| 01 §48-49 Policy（`Contractual distributor boundary` 在 03 DP04 只是一条 hard constraint 示例） | **适用且应升格**：合同边界在中国语境是一等对象，不是约束示例 |
| 02 `ApprovedDecision → TransitionPlan`（交接、赔偿、过渡期） | **高度适用**：经销商更换的过渡治理正是现实痛点 |
| 03 DP03 Territory Alignment | **重新定位**：从"优化对齐"改为"区域治理与证据层" |
| 03 DP01/DP02（定编/驻点） | **适用**：厂家业代团队的 sizing/驻点仍然真实存在 |
| 04 Allocation Intelligence | **高度适用且是最大价值点**：覆盖缺口、能力-潜力错配、窜货信号，全是现实问题 |
| 06 Benchmark | 适用不变 |
| 08 Identity | 适用不变（门店/经销商身份仍是地基） |
| 07 §73-74 Territory Engine（聚类/交换启发式） | **降级为可选**：仅在厂家直营团队内部对齐时使用 |

## 3. 中国语境下 SRAF 真正有价值的四件事

### 3.1 经销商区域台账（治理与审计层）

```text
DistributorContract
    contract_id / distributor_id
    region_terms（区域条款：行政区/街道/商圈/渠道 维度组合）
    exclusive_flag（独家 / 总经销 / 分渠道）
    annual_target（年度任务）
    valid_from / valid_to / renewal_history
    amendment_chain（区域条款变更链：拆分、缩扩、渠道调整）
```

= 把"区域到底分给了谁、依据哪份合同哪条条款、何时变的"变成
可查询、可审计的 bitemporal 台账。今天这件事多数公司靠 Excel + 合同扫描件。

与 08 的衔接：区域条款变更走 `Supersede` 语义（§13），与门店身份无关。

### 3.2 覆盖缺口与越区检测（04 的现实化）

```text
覆盖缺口：哪些门店/商圈不在任何经销商的合同区域内
          （= 新市场空白 / 经销商缩了 / 网格漏划）
越区信号：门店实际进货来源 vs 合同区域不符（窜货 / 越区）
重叠冲突：同一门店被两条区域条款同时覆盖（渠道拆分时常见的灰色地带）
```

这是 `04` H1/H5 的中国化改写，数据源是 POS/订单/门店台账，
不需要算法，需要的是 08 的身份地基 + 规则化检测。

### 3.3 能力–潜力匹配评估（谈判证据层）

```text
区域潜力（DemandSurface，已有）
vs 经销商能力（资金/仓储/车辆/业代数/历史达成）
→ 匹配度报告：这个区域交给这个经销商，够不够？

用途：合同谈判的 evidence base、续约评估、
     新市场招商的能力要求定义。
决策仍是人做（老板拍板），SRAF 提供证据与方案对比
（A0 Advisory，05 §14）。
```

这是 04 §35「Management View」式输出的现实化——书 9.13
performance frontier 的经销商版。

### 3.4 变更影响分析与过渡治理（02 的现实化）

经销商退出/被取消/拆分时的：
```text
受影响门店清单（TransitionPlan 的输入）
过渡期方案（暂由邻区代管 / 短期直营）
库存与客情交接核查清单
```

## 4. 对 MVP 的修订建议（替换原 territory optimizer 计划）

```text
不做：
    territory balancing optimizer
    聚类 / 局部交换 / 旅行距离优化（中国市场无用武之地）

改做（顺序）：
    M1  经销商区域台账（合同区域条款的 bitemporal 登记 + 查询）
    M2  覆盖缺口 / 越区 / 重叠 检测（规则化，挂在 04 诊断之下）
    M3  能力-潜力匹配报告（A0 advisory 输出，供谈判与续约）
    M4  变更影响分析（换商/拆分的 TransitionPlan 输入清单）

仍然保留（与经销商层正交）：
    厂家业代团队的 DP01/DP02/DP06（RTM 拜访体系）
    08 Identity（门店与经销商身份是 M1/M2 的前提）
```
