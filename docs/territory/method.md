# 经销商围栏描述生成方法（v1.0，北区验证通过）

## 数据口径（全部统一 GCJ-02）
| 数据 | 来源 | 说明 |
|---|---|---|
| 基础地块（父） | 边界数据-路网-四级路网 GeoJSON | 2675 个，含 街道[内置] 属性 |
| 街道边界面 | 区划数据-街道 GeoJSON | 228 个街道面，取其 boundary 作界线 |
| 人工围栏 | region.json fences | 手绘，沿地块边+街道界 |
| 道路 | OSM（WGS-84） | 匹配时地块需 gcj2wgs 近似 |

## 管线（三步）

### 1. 规则引擎提取结构化事实（确定性，无 LLM）
- 选中地块：地块与围栏重叠 ≥50% 面积者入选
- 街道构成：按 街道[内置] 归并 → 全覆盖街（100%）/ 部分覆盖街（x/共y）
- 路表：每个选中地块贴路（60m），按街道汇总 → 候选词 "街道沿路: 围栏内x/街道共y"
- 边界带：围栏 − 地块并集 ∩ 街道界线 150m 缓冲 → 无地块带，记录方位与界线名

### 2. 描述词生成（三类词，语义确定）
1. **街道名**：全覆盖街 → 直接用（整街地块全进）
2. **街道沿路**：部分覆盖街 → 选 x=y 的路；一个街可多词；残余用 x/y 最高者补
3. **界带词**：`[方位]至[A街道]—[B街道]界`，几何 = 该界线缓冲带 ∩ 围栏

### 3. 验证（双指标）
- 地块复现 J：hit/(hit+over+miss)，目标 = 1.0
- 围栏 IoU：描述几何 vs 人工围栏，目标 ≥0.93（手绘切地块的粒度极限）

## 北区验证结果
```
凤凰街道
龙洞街道沿华南快速
新塘街道沿广连高速
联和街道沿力康路
西至龙洞街道—长兴街道界
```
25/25 地块零误差，围栏覆盖 99.91%，IoU 0.934。

## 关键教训（不要重蹈）
1. 坐标系：全部数据 GCJ-02，与 OSM 匹配时才转 WGS；meta.crs 误标是 600 米幻移的根源
2. 距离测量不能只量"到边界的距离"，要先查"包含关系"（点在面内时到自身边界距离可以很大）
3. `except Exception: continue` 会吞掉漏 import 的异常（wkt 漏 import 导致路表为空的假象）
4. 贪心/精度优先描述生成器全部废弃——描述词由事实表确定性导出

## 坐标系真相（2026-08-31 最后确认）
| 数据 | 实际坐标 | 证明 |
|---|---|---|
| region.json（围栏） | **WGS-84** | wgs2gcj(region.json) 精确匹配 CSV（GCJ）|
| 四级路网文件（地块） | **GCJ-02** | 用户确认 |
| 区划街道文件 | **GCJ-02** | 用户确认 |

之前误以为 region.json 是 GCJ，一直做 gcj2wgs 转换，导致数据偏西 600m。
正确做法：用 wgs2gcj(region.json) 得到 GCJ 坐标，在高德底图上显示。
编译器运行时必须将 region.json 转为 GCJ 后使用（临时转换，不修改原始文件）。
