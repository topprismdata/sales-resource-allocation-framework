# 基础单元库对比与选型（2026-08-29）

## 检验方法（判决性，非空洞）
质心内单元并集 vs 围栏的 IoU + 骑跨单元数（20%-80% 在内的单元）。
覆盖率检验已废弃（单元铺满全城时对任意多边形都 100%，空洞）。

## 四个候选单元库对比

| 单元库 | 单元数 | 生成方法 | 经销商中位 IoU | 业代中位 IoU |
|---|---|---|---|---|
| 官方四级路网（用户参考件） | 2,675 | 四级路网平面化，街道归属 | 0.764 | **0.970** |
| v3 全 OSM 路网+河+行政界，清碎片 | 46,420 | polygonize + 伪影合并 | **0.969** | 0.769 |
| v4 momepy enclosures 原始 | 115,196 | momepy.enclosures | 0.859 | 0.974 |
| v5 momepy + 伪影清理 + GZ11区裁剪 | 20,493 | 同上 | 0.829 | **0.966** |

（经销商=32 家广州围栏；业代=海珠荔湾 11 片）

## 核心发现

1. **两种"画围栏的语言"并存**：
   - 业代片区按**官方单元层**画（对官方单元 IoU 0.970，零骑跨）
   - 经销商围栏沿**全量路网**画（对 v3 单元 IoU 0.969，含官方库缺的 73% 道路）
2. 两个路网**不嵌套**：官方库 15,583km vs OSM 58,348km，缺 73% 道路，
   面无法互相精确细分——任何单一库都无法同时对两层做到 ≥0.95。
3. 错配归因（分解检验）：经销商围栏错配面积 54-98% 贴 OSM 路 <30m
   （=官方库缺路）；彩弘/鸿欣 34-45% 距任何 OSM 路 >100m
   （=沿了 OSM 也没有的村道，需业务方路网补全）。
4. "人手画不准"被排除：业代片区（同一批内业绘制）贴路中位 0m。

## 选型建议

**双粒度层级库**（两种语言各自保留，附转换映射）：
- L1 业务层：官方 2,675 单元（业代/内业操作用，1:1 对齐现有画法）
- L2 路网层：v3_clean 46,420 面（经销商围栏表达、精细化调整用）
- L1↔L2 映射表：按面积重叠计算，非嵌套处标注"近似"

或按用途选择：业代数据操作用官方单元；经销商重建评估用 v3_clean。
